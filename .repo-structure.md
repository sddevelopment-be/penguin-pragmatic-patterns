# Repository Structure Notes

## Data Directory
- `data/bibliography.toml` provides the site-wide bibliography; Hugo ingests each `[[book]]` table as an individual item.
- Entries share a common field layout:
  - **Required:** `id` (UUID), `title`, `minimized_title`, `authors`, `publisher`, `year`, `link`, `image`, `levels`, `tags`, `description`.
  - **Recommended:** `subtitle`, `location` (publication city), `isbn` (standard for books), `draft`/`unlisted` flags for workflow control.
  - **Optional:** `isbn` may remain empty for non-book resources (articles, essays) that live in the same collection.
- Field conventions:
  - `image` references an asset under `static/images/practices/` or `static/images/books/` depending on how the site templates resolve paths.
  - `levels` must use the complexity categories defined on `content/en/books/_index.md` (Novice-friendly, Intermediate level, Advanced / In-depth, Reference / Comprehensive Guides, Specialized / Niche, Mixed). Localised values should be normalised before publication.
- `tags` reuse the shared taxonomy observed in practices and concepts. Every tag must exist in `data/glossary.toml`; introduce new glossary entries alongside new tags.
- `description` contains supporting HTML (e.g. `<br />`) where needed for Hugo rendering.
- `draft = true` keeps an entry off public listings while retaining it for editorial review. `unlisted = true` marks canonical bibliographic references that should be hidden from navigation but remain available for direct linking.
- `data/bibliography_nl.toml` mirrors the same schema for Dutch content; fewer entries are present and many are still placeholders awaiting localisation.
- `data/glossary.toml` and `data/glossary_nl.toml` hold shared terminology (`[[terminology]]` tables) with `name`, `domain`, `description`, optional `aliases`, and `references`. All tags used in content must exist here.
- `data/tools.toml` / `data/tools_nl.toml` capture tools, websites, and apps referenced by the site. Each `[[tool]]` includes `id`, `title`, `description`, `link`, classification metadata, and image hints.
- `data/presentations.toml` lists presentation assets and metadata (title, slug, tags, image assets) for the presentations section.

## Content Directory
- Top-level locales: `content/en`, `content/nl`; shared pillars live in `content/pillars`.
- `content/en` structure:
  - `books/`: UUID-named Markdown files for each bibliography entry plus `_index.md` describing the taxonomy.
  - `concepts/`: Canonical concept articles; see “Concepts Directory” below for detailed expectations.
  - `glossary/`: Per-term Markdown pages (UUID filenames) expanding glossary entries for site navigation.
  - `practices/`: Core practice library following `TEMPLATE_PRACTICE.md`.
  - `presentations/`: Slide deck landing pages and supporting materials.
  - `tags/`: Hugo tag index pages generated per tag (each `_index.md` with front matter mapping to glossary entries).
  - `tools/`: Long-form write-ups for notable tools/apps (aligned with `data/tools.toml` entries).
- `content/nl` mirrors the English structure with fewer translated artefacts; many files remain absent or carry placeholders awaiting localisation.
- `content/pillars` stores cross-locale thematic pages (e.g., principles or overarching frameworks).

## Concepts Directory
- `content/en/concepts/_index.md` configures the listing page (aliases, outputs, hero image) and frames the knowledge-base narrative around shared vocabulary.
- Individual concept notes live under `content/en/concepts/*.md` and use TOML front matter (`+++`) with a shared section order: Definition, Key Components, Background (Origin / Application / Comparisons), Examples, and Further Exploration.
- `TEMPATE_CONCEPT.md` provides the scaffold for new entries (note the filename typo and the `further_exporlation` misspelling in front matter—use `further_exploration` in published pages). Draft scaffolds such as `behaviour_driven.md`, `project_lifecycle.md`, `Red_and_blue_work.md`, `test_driven.md`, `tool_or_device.md`, and `ubiquitous_language.md` still contain template copy.
- Common front matter fields: `title`, optional `subtitle`, `author`, `description`, `summary`, `categories`, `tags`, canonical `uuid`, mirrored `aliases`, optional `pubdate`, `image`, `related_concepts`, `related_practices`, and `further_exploration`. The latter accepts objects keyed by `type` (e.g. `biblio`, `raw`, `tool`) plus lookup metadata.
- `draft = true` keeps concepts from publishing; currently set on seven files (`behaviour_driven`, `project_lifecycle`, `Red_and_blue_work`, `test_driven`, `tool_or_device`, `ubiquitous_language`, and the template).
- Tag values must exist in `data/glossary.toml`; cross-page relations rely on UUIDs, so ensure new concepts update related practices and concept references where applicable. Several published entries (e.g. `clean-code.md`, `connascence.md`, `ShuHaRi.md`) demonstrate image shortcodes, quotes, and structured bullet lists that downstream templates expect.
