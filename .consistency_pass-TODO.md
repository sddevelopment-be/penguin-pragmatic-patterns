# Concept Consistency Pass — Working Plan

1. **Inventory & Baseline**
   - Generate a manifest of all English concept files (`content/en/concepts/*.md`) noting draft status and UUID alignment.
   - Capture the current scaffold from `content/en/concepts/TEMPATE_CONCEPT.md` to define the target section order and required front matter.

2. **Front Matter Audit**
   - Verify each concept includes mandatory fields: `title`, `uuid`, `aliases`, `description`/`summary`, outputs, and valid `tags`.
   - Cross-check `tags` and `related_*` references against `data/glossary.toml`, practices/concepts UUIDs, and note any missing glossary terms.
   - Entries with `draft` flags reflect publication intent; do not populate these. Take note of them, and write them to `.to-write.md` in the repository root.

3. **Body Structure Review**
   - Ensure sections follow the template order (Definition → Key Components → Background split → Examples → Further Exploration).
   - Flag missing or empty sections, inconsistent heading levels, and deviations in tone or tense from the operational guidance.
   - Record opportunities to align terminology, quotes, and callouts with existing style rules.

4. **Media & Shortcode Check**
   - Inspect image references and shortcodes (quotes, highlights) for broken links or inconsistent paths under `static/`.
   - Note any concept lacking hero/inline assets where the template expects them.

5. **Localization & Cross-Linking**
   - Compare English entries against `content/nl/concepts` to understand translation gaps; document priority candidates for localisation.
   - Review `related_concepts`/`related_practices` lists for symmetry (reverse links) and accuracy.

6. **Remediation Backlog**
   - Produce a change log entry for each concept requiring updates, grouping by issue type (front matter, body structure, cross-links).
   - Do not attempt to fix media issues. Log these in the `.analysis` file in the repository root.
   - Sequence fixes into manageable batches (e.g., five concepts per commit) respecting commit message conventions.

7. **Tooling & Automation Opportunities**
   - Identify checks that could be automated (e.g., front matter validation with a script, glossary tag linting) and outline spike ideas.
   - Write these as a separate header in the `.analysis` file
